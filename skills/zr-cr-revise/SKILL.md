# 真人剧 · 改稿与续写（zr-cr-revise）

目标：**定点改，不推倒重来**；改完仍过字数、格式、红线，并且不破坏后续剧集。

## 五道闸（第四层通用，动笔前先过）

1. **字数闸**：真人剧每集 600 到 800 字，上限 1200（Z1-01）；千部计划每集约 375 到 500 字，40 集共 1.5 万到 2 万字（Z3-01）
2. **纯剧本闸**：投稿正文只能是纯剧本，拍摄执行类、运营标注、修改痕迹、办公备注一律不进正文（M2-08）；说明放进独立的"创作备忘"
3. **旁白闸**：不写上帝视角旁白（M4-13）；OS 依附人物，VO 写明声源（M3-07）
4. **红线闸**：按真人微短剧内容创作建议的严格避免与控量项把关（G4）
5. **依据闸**：行业数据、播放量、分账倍数不作依据；平台没写的只作经验参考并注明"非平台规则"

## 先判断能不能改（必须第一步）

| 状态 | 能否修改 | 规则卡 |
|---|---|---|
| 30 集签约通过后、发起完结申请前 | 所有章节可改或导入替换 | Z2-01 |
| 已发起完结申请 | 任何章节不能改 | Z2-02 |
| 完结安全审核打回 | 可改所有章节，改完重新申请 | Z2-03 |
| 已完结 | 不能改 | Z2-04 |

批量导入按标题匹配：第 X 集覆盖原第 X 集，没有则新增（Z2-05）；改稿交付时保持集标题不变。

## 改稿流程

1. **整理问题清单**：来自第三层诊断报告、平台审核意见或资方意见；按必改、建议改排序；先结构后文本
2. **逐条定点改**：只改问题所在的场次；一条问题一次改动，记录位置与处理方式
3. **连锁影响评估**：改动是否影响后续的伏笔、人物状态、反转的前置信息；同步更新人物状态表与伏笔表（M5-04）
4. **回查**：运行本 skill 目录 scripts/check_script.py（`--mode zr` 或 `--mode qianbu`），再用原诊断 skill 复查问题项；最多两轮

## 常见改法

| 问题 | 改法 |
|---|---|
| 字数超限（超过 1200 必改，超过 800 建议改） | 删复述已知信息的台词；合并功能重复的场次；展示决定后直接跳到结果；一个信息只留一次 |
| 整集严重超长（超过上限一倍以上） | 先列每场功能（推主线、揭关系、造冲突、立人设），只保留承担功能的场；同一功能的场合并；环境与心理描写全部改成一行可拍动作；仍超长时与用户确认是否拆成两集（会改变分集结构，需同步大纲） |
| 整稿不是平台格式（好莱坞格式、小说格式、【】大段描写） | 先整体转成平台模板格式（集标题、场次标题、出场人物、△动作、"人物名（提示）：台词"、OS 与 VO、（本集完）），再做内容定点改；转格式不算改剧情，不需要逐条记录 |
| 场景与演员太多 | 合并场景、合并功能相近的配角；大场面改为小空间里的少数人对抗（Z6-02） |
| 画面感不足 | 导演式优化：把"生气离开"改成一个有后果的动作 |
| 旁白、心理描写 | 改为动作、对白、闪回或简短 OS（M4-13、M5-02） |
| 暴力复仇 | 改为证据、规则、专业能力、公开真相；惩罚交给法律，与过错对等（G4-05） |
| 羞辱动作过密 | 全剧限量，换成口头、能力、身份、权力层面的压制（G4-01） |
| 反派降智 | 给反派合理的不信理由（利益、面子、信息不全）（M4-08） |
| 非纯剧本内容 | 删除 BGM、分镜、运营标注、复盘、修改痕迹（M2-08） |

## 续写

1. 先分析已有剧集：类型、风格、声线、人物状态、已用过的钩子与爽点类型、未回收的伏笔
2. 对照大纲与分集卡确定接下来的任务；没有就先补（zr-cr-outline）
3. 按同一风格写，上一集悬念在前 3 行接住（单集写法同 zr-cr-episode）

## 交付

1. **正文**：修改后的完整集（整集替换，集标题不变）
2. **创作备忘**：改动清单（问题、位置、处理方式、规则卡）；连锁影响与同步更新；改后字数；未采纳的意见及原因

## 示例

### 正例一：主场景（按意见压缩超字数）
**输入**：第 7 集 1500 字，平台要求不超过 1200，帮我压。
**输出**：改动清单（放创作备忘）：
```
1. 7-2 场删去周倩复述上一集事件的 3 句台词（信息已知）
2. 7-3、7-4 两场功能重复，合并为一场
3. 林晚做决定后直接跳到结果，删去犹豫过程
改后字数：960
```
**为什么好**：定点改、不推倒；改完仍过 1200 上限（Z1-01）；改动记录与正文分开交付。

### 正例二：边缘场景（已发起完结申请）
**输入**：我已经申请完结了，还想改第 20 集。
**输出**：发起完结申请后任何章节都不能改（Z2-02）；如果安全审核打回，才能改所有章节并重新申请（Z2-03）。现在可以先把修改稿备好。

### 反例一：质量不足
**错误输出**：只改了第 7 集，没有检查第 12 集还在引用被删掉的那句台词。
**问题**：缺连锁影响评估，前后对不上（M5-04）。**改法**：改完同步人物状态表与伏笔表。

### 反例二：越界过度
**错误输出**：用户只要压字数，结果把整集重写，换了反转和结局。
**问题**：超出改稿范围，破坏后续剧集。**改法**：大改结构先回 zr-cr-outline 与用户确认。

## 边界

- 完结申请后或已完结状态下，不给出"上传替换"的建议
- 大改结构时先回 zr-cr-outline
