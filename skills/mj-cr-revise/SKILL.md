# AI漫剧 · 改稿与续写（mj-cr-revise）

目标：**定点改，不推倒重来**；改完仍过体量、格式、红线、可画性，并且不破坏后续剧集与已定的角色形象。

## 五道闸（第四层通用，动笔前先过）

1. **字数闸**：长篇超过 70 集、全剧不低于 7 万字（折算约每集 1000 字），单集观看 1 到 2 分钟（M1-01、M1-02）
2. **纯剧本闸**：投稿正文只能是纯剧本，分镜、提示词、资产卡、运营标注、修改痕迹一律不进正文（M2-08）；说明放进独立的"创作备忘"
3. **旁白闸**：不写叙述旁白与第一人称解说；成品框架分成合作不收旁白解说类（M1-04、M4-13）；OS 依附人物，VO 写明声源（M3-07）
4. **红线闸**：漫剧红线比真人剧更严（G4 加 M8），剧本里写的都会被画出来
5. **依据闸**：行业数据、播放量、分账倍数不作依据；平台没写的只作经验参考并注明"非平台规则"

## 先判断所处阶段（必须第一步）

| 阶段 | 能改什么 | 注意 | 规则卡 |
|---|---|---|---|
| 投稿前 | 全部可改 | 改完简介、大纲、人设与正文保持一致；正文按集数顺序 | M2-07 |
| 退稿后重投 | 按退稿原因整改；集数与体量要重新达标 | 退稿原因逐条对照"常见改法"表；平台未公布 AI 剧剧本的改稿时间窗，以站内通知为准（待核） | M5、M4 |
| 成片已上传（版权方） | 剧壳与正片在「红果版本」「抖音版本」→「版本编辑」中修改 | 承诺总集数、"是否 AI 作品"不可改；改剧名要补《剧名确认书》；审核意见可在版权后台导出对照修改 | M1-07、G1-05 |

改稿交付时保持集标题不变（中文数字"第一集"），整集替换。

## 改稿流程

1. **整理问题清单**：来自第三层诊断报告、退稿原因、审核意见或合作方意见；按必改、建议改排序；先结构后文本
2. **逐条定点改**：只改问题所在的场次；一条问题一次改动，记录位置与处理方式
3. **连锁影响评估**：改动是否影响后续的伏笔、人物状态、反转的前置信息、力量体系规则；同步更新设定与人物状态表、伏笔表（M5-04）
4. **形象一致检查**：涉及角色外形、服装、标志物的改动，同步角色形象锚点卡；外形一旦确定全剧一致（M9-05、M8-08）
5. **回查**：运行本 skill 目录 scripts/check_script.py `--mode mj`，再用原诊断 skill 复查问题项；最多两轮

## 常见改法

| 问题 | 改法 |
|---|---|
| 旁白解说、第一人称解说 | 改成多角色对话与表演推动：信息交给对手戏、可见物证、动作结果；保留的 OS 少量且依附人物（M4-13、M1-04、M3-07） |
| 只转格式不做戏剧化 | 以"场"为单位重写，每场有冲突、动作与结果；叙述句不直接变旁白（M5-02） |
| 动作行不可画 | 主语明确，一行一个主要动作；抽象心理改成表情、手部动作、道具与环境反应（M3-04） |
| 大场面细节空 | 落到可见细节：谁的手在抖、哪件东西先碎、谁先开口、旁人什么反应（M5-03） |
| 设定轰炸 | 用事件演规则，一次只给一条；复杂设定精炼而不是删光（M5-07） |
| 篇幅不足或注水 | 全剧不低于 7 万字、超过 70 集（M1-01）；补的是有效推进（目标、关系、冲突、信息、后果），不补过场（M4-10、M5-09） |
| 单集过长 | 删复述已知信息的台词；合并功能重复的场次；一个信息只讲一次（M5-12），单集按观看 1 到 2 分钟控制（M1-02） |
| 情绪链断 | 打压后补反击，反击后补反派、旁观者、主角自己的反应（M5-06） |
| 血腥、恐怖、扭曲形象 | 去写实血腥（模糊处理后仍写实也违规）；怪异扭曲恐怖控量；奇观改用觉醒、天地异象、超现实空间（M8-04、M8-05） |
| 暴力复仇、过度报复 | 惩治与过错对等；现代背景改为证据、规则、专业能力、公开真相（G4-05、M8-03） |
| 羞辱动作过密 | 全剧限量，换成口头、能力、身份、权力层面的压制（G4-01） |
| 反派降智 | 给反派合理的不信理由（利益、面子、信息不全）（M4-08） |
| 视角漂移 | 事件收束回主角，配角反应只写主角在场可见的（M5-08） |
| 整集严重超长（超过上限一倍以上） | 先列每场功能（推主线、揭关系、造冲突、立人设），只保留承担功能的场；同一功能的场合并；环境与心理描写全部改成一行可拍动作；仍超长时与用户确认是否拆成两集（会改变分集结构，需同步大纲） |
| 整稿不是平台格式（好莱坞格式、小说格式、【】大段描写） | 先整体转成平台模板格式（集标题、场次标题、出场人物、△动作、"人物名（提示）：台词"、OS 与 VO、（本集完）），再做内容定点改；转格式不算改剧情，不需要逐条记录 |
| 非纯剧本内容 | 删除分镜、景别、提示词、资产卡、BGM、运营标注、复盘、修改痕迹（M2-08） |
| AI 痕迹 | 去掉破折号、来回说同一件事、书面化台词与小说原句；遮住名字也能分清谁在说（M5-13、M5-12） |
| 魔改原著（改编作品） | 恢复原著核心设定与核心情绪，重构只服务戏剧化表达（M5-11） |

## 续写

1. 先分析已有剧集：类型、男女频、风格、声线、人物状态、力量等级、已用过的钩子与爽点类型、未回收的伏笔
2. 对照全剧大纲与分集卡确定接下来的任务；没有就先补（mj-cr-outline）；钩子分布守住前 5 集至少 1 个、之后每 10 集至少 1 个强钩子（M4-14），每 2 到 3 集一个新信息点（M4-11）
3. 按同一风格写，上一集悬念在开头接住，可复现上一集结尾 1 到 3 行承接（M3-10）；集尾停在未完成的动作、危险、误会、身份揭示或关系推进上，写"（本集完）"（M3-11、M3-12）
4. 新出场角色首次正式出场交代核心视觉信息并加人物字幕（M3-05），同步写入形象锚点卡

## 交付

1. **正文**：修改后的完整集（整集替换，集标题不变），纯剧本
2. **创作备忘**（与正文分开）：改动清单（问题、位置、处理方式、规则卡）；连锁影响与同步更新；形象锚点变更；改后字数与全剧累计字数；未采纳的意见及原因

## 示例

### 正例一：主场景（旁白改对话）
**输入**：被退稿，原因是旁白太多。原文：
```
【旁白】沈烬知道，这是器灵在帮他，而赵玄还蒙在鼓里。
```
**输出**：
```
△炉火忽然一暗，沈烬低头看向手腕的铁链。
【VO】器灵（低声）：别急，他还没看出来。
△赵玄抱着手臂，盯着炉口，没注意到铁链在发光。
```
**为什么好**：信息交给对手戏和可见物证，VO 写明声源（M4-13、M3-07），可画。

### 正例二：边缘场景（成片已上传想改集数）
**输入**：上传时承诺 80 集，现在想写到 120 集。
**输出**：承诺总集数不可修改，连载上传到该集数后自动完结（M1-07）。只能在剧情内收束，或另立新作（系列剧）再上传。

### 反例一：质量不足
**错误输出**：只删掉了"【旁白】"三个字，内容原样留成动作行。
**问题**：只改格式不做戏剧化（M5-02）。

### 反例二：越界过度
**错误输出**：用户只要改旁白，结果把角色外形也重新设计了。
**问题**：改动形象会破坏全剧一致性和已有确权（M9-05）。形象大改要先过 mj-dx-visual。

## 边界

- 不改承诺总集数、"是否 AI 作品"等不可改项，也不建议绕开
- 大改结构时先回 mj-cr-outline；形象大改先过 mj-dx-visual
- 改完交第三层复查：mj-dx-rejection、mj-dx-redline、mj-dx-visual
