# 真人剧 · 投稿包诊断（zr-dx-package）

回答一个问题：**这份材料现在交到短剧创作者中心，平台收不收？**

## 输入

- 必需：剧本正文（至少 30 集）、人物小传、大纲
- 尽量提供：剧名、选择的篇幅（短篇、中短篇、长篇）、是否参加千部计划、是否 IP 改编及授权情况、是否已有投资出品方、当前剧本状态（未投稿、已签约未完结、已申请完结）
- 缺必需材料时，先列出缺什么，再对已有材料做部分诊断

## 检查清单

### A. 材料齐全（必改级）
| 项 | 标准 | 规则卡 |
|---|---|---|
| A1 | 首次投稿完整 30 集正文 | Z1-02、Z1-04 |
| A2 | 有人物小传和大纲；批量导入放第 0 集，单独上传放第 1 集且剧情顺延 | Z1-02 |
| A3 | 千部计划：40 集全集，总字数 1.5 万到 2 万，选「短篇」，剧名前加【全集】，未投产 | Z3-01、Z3-02 |

### B. 篇幅与完稿规划
| 项 | 标准 | 规则卡 |
|---|---|---|
| B1 | 选定篇幅与完稿集数对应：长篇不少于 80 集，中短篇不少于 60 集，千部计划 40 集 | Z1-03 |
| B2 | 大纲覆盖到完稿集数，按阶段写完整，不只写前几集（借用平台《AI剧自制编剧投稿模板》写法：每 10 集一段，写主线、关键冲突、重要反转、阶段看点） | M2-03 |
| B3 | 若可能被平台签委托协议，提醒：签约后不论资方是否选中都要写完全集 | G5-06 |

### C. 原创、授权与首发（必改级）
| 项 | 标准 | 规则卡 |
|---|---|---|
| C1 | 原创、自有 IP 改编或平台授权 IP 改编；投稿前未在其他平台推进生产或公开发布；不一稿多投 | G5-01 |
| C2 | 使用平台 IP：已在「剧本创作-IP选取」申请通过 | G5-02 |
| C3 | 千部计划：此前未向第三方投稿、授权、转让（含出版、信息网络传播、改编摄制），未公开发布 | Z3-06 |
| C4 | 已签《个人编剧入驻协议》 | G5-03 |
| C5 | 正文、剧名是否明显借用他人作品的标志性台词、角色名或名场面：已获授权备好授权链；未获授权列"人工判断"并建议替换 | G5-01 |

### D. 资方选项
| 项 | 标准 | 规则卡 |
|---|---|---|
| D1 | 新建剧本时"是否已有投资出品方"如实选择；选"已有"即不签平台委托协议，30 集审核后把剧本 ID 给资方报备 | G5-04 |

### E. 一致性（借用平台《AI剧自制编剧投稿模板》要求）
| 项 | 标准 | 规则卡 |
|---|---|---|
| E1 | 小传、大纲与正文设定一致（人名、身份、关系、关键事件） | M2-07 |
| E2 | 人物小传包含姓名、性别、年龄、身份、性格、人物目标、与主角关系（建议每人 50 到 100 字） | M2-04 |
| E3 | 剧名、简介与正文一致，不套壳 | G2-06 |

### F. 剧名（必改级）
| 项 | 标准 | 规则卡 |
|---|---|---|
| F1 | 不超过 20 个字符，不含书名号、尖括号、空格 | G2-04 |
| F2 | 标点只用逗号、感叹号、冒号、问号、双引号 | G2-05 |
| F3 | 不含营销词与无关词，不蹭热剧热演员，不与已发布或高热预约剧名完全重复 | G2-01、G2-07 |
| F4 | 头部 IP 改编完整包含 IP 名；非头部 IP 不含平台保护的作品名 | G2-02 |

| 项 | 标准 | 规则卡 |
|---|---|---|

| G3 | 安全审核打回：可改全部，改完重新申请 | Z2-03 |
| G4 | 已完结：不能改 | Z2-04 |

## 流程

1. 收材料，按 A 到 G 逐项打勾
2. 抽查正文的格式与字数：建议同时运行 zr-dx-episode 的机检脚本
3. 抽查小传、大纲与正文的一致性：至少核对主角、主要反派、核心关系、前 3 集事件
4. 按报告格式输出；保底金额、分成比例只能引用规则卡并提示"以站内信和合同为准"

## 诊断纪律（第三层通用）

- **只诊断，不写稿**：可以给一句修改方向或一行示意，不重写段落；改稿交给第四层（zr-cr-outline、zr-cr-character、zr-cr-revise）
- **每条问题都要有出处**：位置（第几集第几场或第几行）、规则卡编号、原文要点
- **分级**：
  - 必改：违反【硬】规则，不改会退稿、驳回或无法上线
  - 建议改：违反【控】规则或【荐】写法，影响评级或过稿率
  - 人工判断：关键词或情节存在风险，需要结合上下文确认
- **不凭经验加规则**：规则卡没有的标准不作为扣分依据，可在"补充意见"里单列并注明"非平台规则"
- **时效**：引用有截止日期的规则（如千部计划 2026-12-31）时，先对照当前日期

## 报告格式（固定）

```
诊断结论：可投 ／ 需改后投 ／ 不建议投
一句话理由：……

一、必改（共 N 条）
| # | 位置 | 问题 | 规则卡 | 修改方向 |

二、建议改（共 N 条）
| # | 位置 | 问题 | 规则卡 | 修改方向 |

三、人工判断（共 N 条）
| # | 位置 | 风险 | 规则卡 | 判断要点 |

四、通过项
- 逐项列出已检查且合格的项目

五、交接
- 交给哪个第四层 skill 改，按什么顺序改
```

结论判定：有任何一条"必改"即不能判"可投"；必改项集中在价值观红线或"小说直转、AI 直出"时判"不建议投"。

## 示例

### 正例一：主场景（投稿前体检）
**输入**：30 集正文、人物小传、大纲都齐了，帮我看能不能投。
**输出**（报告节选）：
```
结论：需改后投
| 级别 | 位置 | 问题 | 规则卡 |
| 必改 | 小传 | 周倩小传写"28 岁"，正文第 5 集写"三十岁生日" | M2-07 |
| 建议改 | 大纲 | 第 21 到 30 集只有一句话，资方看不出后段走向 | Z6-02 |
| 通过 | 正文 | 30 集齐全，单集字数 620 到 790 | Z1-01 |
```
**为什么好**：先给结论，问题按级别排序，每条都有位置和规则卡；只诊断不改写。

### 正例二：边缘场景（千部计划）
**输入**：这是千部计划的稿子。
**输出**：改按千部计划核对：40 集全集、总字数 1.5 万到 2 万（Z3-01）、投稿选「短篇」且剧名前加【全集】（Z3-02）、未投产且未向第三方投稿或发布（Z3-06）。

### 反例一：质量不足
**错误输出**：`整体不错，可以投，建议再打磨一下人物。`
**问题**：没有逐项核对，没有位置和依据，用户不知道改哪里。

### 反例二：越界过度
**错误输出**：诊断完顺手把人物小传全部重写了一遍。
**问题**：诊断型只给问题和方向，改写交给第四层（zr-cr-character）。

## 边界

- 不判断剧本好不好看；内容质量交给 zr-dx-opening、zr-dx-rhythm、zr-dx-rejection
- 不判断红线；交给 zr-dx-redline
- 不代替用户在平台上操作；操作步骤交给 zr-submit-sign
