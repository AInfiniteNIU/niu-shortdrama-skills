短剧创作者中心 skill 系统 使用手册与指南

面向在红果短剧创作者中心工作的编剧、导演、演员与版权方：从入驻、投稿签约、撮合、上线、结算，到写剧本、诊断退稿，两套系统一站解决。

非官方项目，与红果短剧、抖音及其关联公司无关；规则以平台站内公告与合同为准。依据：短剧创作者中心帮助中心 37 篇官方文档（抓取并复核于 2026-11-17），规则卡库 v1.1。

快速上手

1. 安装

  1. Claude Code 用户：运行 /plugin marketplace add AInfiniteNIU/niu-shortdrama-skills，再按需安装 zhenren（真人剧）或 manju（AI 漫剧）。
  2. 其他用法：到 Releases 下载 zip，或克隆仓库，把 skills/ 下需要的文件夹整个放进你的 skills 目录（每个文件夹含 SKILL.md，部分含 scripts/check_script.py）。
  3. 建议至少同时装上对应系统的总入口：做真人剧装 zhenren-hub，做漫剧装 manju-hub；两套都做就全装。

2. 三种用法

用法怎么说适合
直接说事“首次投稿要交多少集？”“帮我看看这份投稿包能不能投”大多数情况，系统自动路由到对应 skill
点名调用“用 zr-dx-episode 帮我查一下第 3 集”你已经知道要用哪个 skill
先问总入口“这个问题归哪个工具管？”不确定从哪里开始
每个 skill 文末都附有它引用的规则卡全文，单独安装也能用，不必另查平台文档。

3. 先说清是真人剧还是漫剧

两套系统并行。没说品类的短剧请求，默认按真人短剧处理；漫剧 skill 只在你提到漫剧、AI剧、动态漫、AI仿真人剧或动画微短剧时触发。所以做漫剧时，第一句话带上“漫剧”两个字最稳。

体系架构

两套系统（真人剧 zhenren-hub + zr 系列，AI 漫剧 manju-hub + mj 系列）各分四层。上层回答“是什么、去哪里”，下层负责“怎么办、行不行、帮我写”。

第一层 路由 2 个

知识库与路由：回答平台规则，内置完整规则卡库与 20 条冲突裁决，把需求分发给下层

第二层 办事 12 个

平台办事：入驻认证、投稿签约、撮合、上传审核、结算数据、剧组与形象确权，只讲怎么操作

第三层 诊断 15 个

只诊断不写稿：投稿包、单集、开篇、节奏、红线、退稿、上线、资方视角、画面可生成性

第四层 创作 21 个

负责写：选题、主线、人物、大纲、开篇、分集、台词、改编、长线、改稿续写，写完交第三层自检

典型工作流

A. 真人剧编剧：从选题到投稿签约

zr-cr-topic 选题立项→zr-cr-mainline 主线设定→zr-cr-character 人物→zr-cr-outline 大纲与分集卡→zr-cr-opening 开篇→zr-cr-episode 分集→zr-dx-episode / zr-dx-package 自检→zr-submit-sign 投稿签约

要点：首次投稿交完整 30 集（含人物小传与大纲）；单集 600-800 字，不超过 1200 字；完稿长篇不少于 80 集、中短篇不少于 60 集。

B. 漫剧编剧：从选题到投稿包

mj-cr-topic→mj-cr-world→mj-cr-character（形象锚点）→mj-cr-outline（13 项附件）→mj-cr-opening→mj-cr-episode→mj-dx-visual / mj-dx-package→mj-submit-sign

要点：长篇超过 70 集、不低于 7 万字；首发卡点按投稿模板“大于 100 集”；正文必须是纯剧本，剔除分镜、修改痕迹等 6 类内容。

C. 被退稿了

zr-dx-rejection / mj-dx-rejection 体检→对应专项诊断（开篇、节奏、红线）→zr-cr-revise / mj-cr-revise 改稿→再跑诊断复查

D. 成片要上线

zr-dx-release / mj-dx-release 上线前自查→zr-release-ops / mj-release-ops 上传审核→zr-settle-data / mj-settle-data 结算与数据

E. 资方、导演、演员

资方选本用 zr-dx-buyer；撮合用 zr-matchmaking；导演、演员与演员机构入驻经营用 zr-crew；漫剧虚拟形象创建与确权用 mj-avatar。

用好它的技巧

先诊断，再改稿

第三层只出问题清单，不动稿；确认后再交第四层改，避免把没问题的地方也改了。

一次只办一件事

“查开篇”和“改开篇”分开说，路由更准。

贴原文

诊断时直接贴剧本或附件，系统会标到第几集第几行和规则卡编号。

带上品类和阶段

“漫剧、已签 30 集、准备完结”这样的上下文能让回答直接落到对应规则。

续写交改稿 skill

“接着写下一批”统一由 zr-cr-revise / mj-cr-revise 处理，它会先读前文与台账。

看状态列

规则卡标“已截止”“已暂停”的政策不要再按它准备材料。

常见问题

能不能只装一个 skill？

可以。每个 skill 都附有引用规则卡全文，单独可用；但装上对应 hub 后，提问不准时能自动转到正确的 skill。

为什么我问漫剧的问题却答了真人剧？

没提品类时默认按真人短剧处理。第一句话带上“漫剧”“AI剧”或“动态漫”即可。

系统会替我登录平台或填表吗？

不会。办事 skill 只告诉你怎么准备、怎么交、注意什么，不替你登录、填写证件或付款。

平台政策变了怎么办？

按更新机制：先改规则卡状态，再改引用它的 skill；重新跑一遍触发测试问法。

机检脚本报“必改”一定要改吗？

“必改”对应硬规则，不改会退稿或审核不过；“建议改”影响过稿率；“人工判断”需要结合上下文。

边界、时效与版本

  • 不替用户做平台操作，不代填证件、不付款。
  • 金额、比例、日期最终以站内信与合同为准。
  • 平台文档未覆盖的事项标“待核”。
  • 不写分镜、镜头语言与视频提示词（漫剧生产衔接只到 mj-cr-handoff 的交接清单）。
